## Feature: Paid self-registration (no invite code required)

Allow users to register **without an invite code** by purchasing a Basic/Pro/Max plan at signup. Invite-code registration stays fully intact. Account is created in an inert `pending_payment` state and is **completely deleted after 2 hours if unpaid** (cron-driven, with a lazy safety net). The paid-registration endpoint is rate-limited to **1 request / 24h per IP**.

This follows the AI-DLC workflow: Jira task first, context updates before/after, no infra names in UI.

### 2. Backend — paid registration endpoint

**New** `POST /api/auth/register-paid` in `backend/app/api/auth.py` (kept here next to `register` for discoverability).

- **Payload:** `RegisterPaidPayload { email: EmailStr, password: str, display_name: Optional[str]="User", plan: Literal["basic","pro","max"], billing_cycle: Literal["monthly","quarterly"] }`.
- **Gating:** read `registration_mode` from `app_settings`; reject with 403 if mode is `invite_only`.
- **Rate limit:** `rate_limiter.check_and_record("auth_register_paid", client_ip)` — new rule (see §5): **1 req / 86400s / IP**. Counted on every hit (like `auth_register`), so a failed attempt still consumes the daily slot.
- **Validation (mirror existing `register`):** password strength via `validate_password_strength`; email not already registered; **also** reject if the email matches an existing `pending_payment` account (return a clear message to finish checkout or wait).
- **Plan validation:** confirm `plan_is_active_<tier> == "1"` and that `polar_product_id_<tier>_<cycle>` is a valid UUID (`_is_uuid_shape`); reject otherwise with "Selected plan is not available."
- **Create user (inert):** `roles=["free_user"]`, `is_active=false`, `pending_payment_since=now`, `plan_started_at=now`, `plan_ends_at=None`. Seed `local_profiles`, `user_usage_stats`, `document_categories` exactly as `register` does today.
- **Create Polar checkout** by extracting the existing `create_polar_checkout` core (auth.py:514–597) into a reusable helper `_create_polar_checkout_session(user, product_id, success_url, settings) -> str` (also reduces auth.py bloat — see §7). Call it with `external_customer_id=user.id`, `customer_email=user.email`, `success_url` validated via `_is_allowlisted_success_url`. If Polar returns no URL → **delete the just-created user row** (no orphan) and return 400.
- **Response:** `{ status: "success", checkout_url }`. Frontend redirects there.
- Webhook reconciliation needs **no new lookup** — `_find_user` (webhooks.py:197) already falls back to `email` and backfills `polar_customer_id`, which is exactly the contract a "user created before payment" flow needs.

### 3. Backend — webhook activation

In `handle_subscription_updated` (`backend/app/api/webhooks.py`, after the existing role-swap + plan-dates block), add: if `user.pending_payment_since is not None`, set `user.is_active = True` and `user.pending_payment_since = None`. Edge case to handle explicitly: if the webhook for a `pending_payment` user fails to find the user (already purged by the 2h cron), the existing `raise HTTPException(500, "User not found")` already surfaces it for Polar retry — acceptable, since the account is gone.

### 4. Cleanup — 2h TTL on unpaid accounts

Single source of truth + three triggers (cron primary, lazy safety net, manual admin).

- **Purge function** in new `backend/app/services/registration_cleanup.py`:
  `purge_expired_pending_accounts(store, older_than_hours=2) -> int`.
  `DELETE FROM users WHERE pending_payment_since IS NOT NULL AND is_active = false AND pending_payment_since < NOW() - INTERVAL '2 hours'` (+ explicit dependent deletes if FKs don't cascade). Returns count. Logs count + sample ids. Idempotent.
- **Internal endpoint** `POST /api/internal/cleanup-pending` gated by a shared secret header `X-Cleanup-Token` matched against env `CLEANUP_SECRET` (mirrors the `POLAR_WEBHOOK_SECRET` pattern — no admin login needed, safe for external schedulers). Calls the purge function, returns `{ deleted }`.
- **Admin endpoint** `POST /api/admin/cleanup/pending-accounts` (`require_super_admin`) — manual trigger + returns count. Surface a button in the admin Settings tab.
- **Standalone script** `scripts/cleanup_unpaid_pending.py` — imports the purge function and runs it (for manual runs / future Render Cron Job).
- **Lazy safety net** — on a cheap read path (`/api/auth/login`), if `NOW() - last_pending_cleanup_at > 2h`, run the purge and update `last_pending_cleanup_at`. Matches the codebase's lazy-expiry pattern (invite codes, usage-stat resets, rate-limit pruning). Keeps accounts reaped even if the external cron ever misses.
- **GitHub Actions cron** `.github/workflows/cleanup-pending-accounts.yml`:
  `on: schedule: cron: "0 */2 * * *"` → `curl -X POST $BACKEND_URL/api/internal/cleanup-pending -H "X-Cleanup-Token: $CLEANUP_SECRET"`. This is the **free, reliable 2h cron** the zero-cost constraint requires (Render Cron Jobs are paid; in-process loops die on free-tier sleep). Secret stored as a repo Actions secret.

### 8. Tests (`scholardocx-test-cases` skill)

- **`register-paid` validation:** rejects weak password, duplicate email, inactive/unconfigured plan, wrong `registration_mode`; creates an inert user (`is_active=false`, `pending_payment_since` set) on success and returns a checkout URL.
- **Rate limit:** second call within 24h from same IP → 429; rule appears in `catalog()`.
- **Webhook activation:** `subscription.created` for a `pending_payment` user → `is_active=true`, `pending_payment_since=NULL`, roles swapped to the paid plan.
- **Purge function:** deletes only rows with `pending_payment_since < now−2h AND is_active=false`; leaves active, paid, and invite-registered users untouched; returns correct count; idempotent on re-run.
- **Login pending message:** login against a `pending_payment` account returns the "being activated" message (not the generic deactivated one).
