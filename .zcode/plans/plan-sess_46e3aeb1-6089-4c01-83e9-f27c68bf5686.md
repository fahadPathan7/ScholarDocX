# Plan: Cell Text & Cell Formatting for Sheets (SCHOLARDOCX-0119)

## Decision (confirmed with you)
**Scope:** Core set **+ curated font family** — Bold/Italic/Underline, Strikethrough, Text color, Cell background, Row background, Alignment (L/C/R), Font size presets, and a small system-font list (Sans / Serif / Mono).
**Interaction:** **In-cell format bar** — a compact toolbar appears above the cell while it's being edited.

## Architecture (validated against your codebase)

Your sheet is a custom `<table>`. Rows are `Record<string, string>` persisted as a JSON blob (`rows_json` on one `project_pages` row). The `_height` key already proves reserved `_`-prefixed metadata can ride along on rows and round-trip through CSV/paste/undo/AI without changes. We reuse that exact pattern.

**Storage decision:** Store styles as **JSON-string values** on reserved row keys (mirrors `_height`), NOT as a new DB column and NOT as localStorage:
- `_cellStyles` → `JSON.stringify({ "University name": { bold: true, color: "#c00", ... } })`
- `_rowStyle` → `JSON.stringify({ bg: "#eef" })`

Why this and not alternatives:
- **vs. localStorage (Date Colors):** formatting must survive across sessions/AI edits → belongs in `rows_json`.
- **vs. new `cell_styles_json` DB column:** a column forces a backend migration, schema/doc updates, and parallel AI-read wiring. A row-local key needs **zero backend changes**.
- **vs. native object values:** row type is `Record<string, string>` everywhere; JSON-string keeps types consistent with `_height`.

Validated safe paths (no changes needed):
- **CSV export / paste** (`sheetCsv.ts`, `sheetPaste.ts`): iterate over `columns` only → `_` keys never leak. ✓
- **Undo/redo** (`useUndoRedo`): snapshots whole rows array → styles participate automatically. ✓
- **AI row updates** (`ai_actions_execute.py:197`): uses `row.update(...)` → preserves existing `_cellStyles`. ✓
- **AI row creation** (`row_for_columns`): filters to column names, but new rows have no styles anyway. ✓

## Implementation steps

### Step 1 — Types & model (`sheetModel.ts`)
Add the `CellStyle` type, the `FONT_SIZES` / `FONT_FAMILIES` presets, a `cellStyleToCss()` helper (style → React CSSProperties), and `parseCellStyles()` / `parseRowStyle()` safe-JSON parsers. Add an `applyCellStyle()` mutator that merges a partial style onto a row's `_cellStyles[colName]` and deletes keys when toggled off.

**Style keys:** `bold`, `italic`, `underline`, `strike`, `color`, `bg`, `align` (`"left"|"center"|"right"`), `fontSize` (`"sm"|"md"|"lg"|"xl"`), `fontFamily` (`"sans"|"serif"|"mono"`).

### Step 2 — `useSheetPage.ts`: `saveCellStyle(rowIndex, colName, partial)` + `saveRowStyle(rowIndex, partial)`
Mirror the existing `saveCellValue` shape: immutable update → push undo snapshot → `persistPage()` (which already PATCHes `rows_json`). Expose both in the hook return. Also thread `cellStyles`/`rowStyle` through any row-clone sites so `_height`/`_cellStyles`/`_rowStyle` are preserved together.

### Step 3 — New `CellStyleBar.tsx` component
A compact horizontal toolbar:
`[B] [I] [U] [S] │ [A▼ color] [🪣 bg] │ [≡L][≡C][≡R] │ [Size▼] [Font▼] │ [Clear]`
- Toggle buttons read active state from the current `CellStyle`.
- Color pickers use native `<input type="color">` + a small preset swatch row (reuse the restrained palette from `frontend-visual-system.md`).
- `Clear` resets the cell to default.
- Compact, themed via existing CSS vars; positioned to sit directly above the edited cell.

### Step 4 — Wire the bar into editing (`SheetTableRow.tsx`)
When `isEditing && col.type !== 'file'`, render `<CellStyleBar>` immediately above `<InlineCellEditor>` inside the `<td>` (positioned absolute/floating so it doesn't distort row height). Pass current `CellStyle` + the `saveCellStyle` callback. Hidden for file cells (consistent with existing rule).

### Step 5 — Apply styles in render
- **Cell-level layout** (`SheetTableRow.tsx:134`, the `<td style>`): merge `align` + `bg` (cell background) + `rowStyle.bg` (row background, cell bg wins if both) + `fontFamily`/`fontSize` (so the whole cell, not just the inner span, reflects them).
- **Inner text** (`SheetRecordFields.tsx:575`, the `<span>`): merge `bold`/`italic`/`underline`/`strike`/`color`. Done via `cellStyleToCss()`.

### Step 6 — Full-cell editor parity (`SheetRecordFields.tsx` viewer, ~line 425)
Add the same `CellStyleBar` to the expand-to-view modal so formatting is reachable from long-text editing too (not only inline). Reuses the exact same component — single source of truth.

### Step 7 — Row-level formatting affordance
Row background: add a small "Row color" swatch control to the existing per-row actions area (next to Peek/Edit in `SheetTableRow.tsx:177`) — sets `_rowStyle.bg`. Low cost since the storage/render plumbing is shared.

### Step 8 — CSS polish (`frontend/src/styles/`)
Add `.cell-style-bar` styles, swatch grid, active/toggle states. Honor the visual contract: compact, native-spreadsheet feel, no fade blocks, whole-cell interactivity preserved. Verify dark-mode tokens.
