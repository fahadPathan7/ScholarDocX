# Sheet "Ask AI" → context-aware prompt catalog with action execution

## Goal

Replace the single hardcoded "analyze this sheet" prompt with a **dropdown catalog of 8–10 useful, action-oriented prompts** plus a custom-text option. Selected prompts pre-fill Lumi (manual send, per your choice), carry sheet schema + selection context, and route through the existing `/ai/actions/*` execution layer so the AI can actually create/update/fill rows, not just chat.

## What already exists (no backend work needed)

- **Agentic action layer**: `/ai/actions/plan` → `/ai/actions/execute` with 60+ action types including `add_rows`, `update_row`, `bulk_update_rows`, `filter_rows`, `analyze_sheet`, `add_column`, `clear_sheet`, `search_rows`. (`backend/app/services/ai_actions*.py`)
- **Pre-fill bridge**: `scholardocx:open-ai` CustomEvent with `{ contextMessage }` → FloatingAssistant opens and seeds its textarea. (`FloatingAssistant.tsx:177-187`)
- **Sheet context in scope at `onAskAI`**: `sheet.columns`, `sheet.rows`, `sheet.focusedCell`, `sheet.selectedRows`, `selectedSheet`, `selectedPage`, `selectedProject`. (`ProjectWorkspace.tsx:741`)
- **Looks-like-action detection**: FloatingAssistant already routes action-looking messages to `/ai/actions/plan` and shows Confirm/Cancel for writes. (`FloatingAssistant.tsx:53-58, 458-470`)

So the feature is purely a **new frontend module** (prompt catalog + dropdown) plus a small change to how `onAskAI` builds context. No backend, no new endpoints, no DB changes.

## Design decisions (confirmed with you)

- **UI**: dropdown/popover anchored to the "Ask AI" button. Catalog grouped by **Analyze / Fill & Transform / Selection-aware**.
- **Send behavior**: pre-fill Lumi's input (existing path), user hits Send. No imperative-handle refactoring of FloatingAssistant.
- **Context**: column names/types + row count + selection/focused-cell info + project/sheet name. **No cell values** (matches the planner's design — it never sees values; it uses read actions when needed).

## Implementation

### 1. New module: `frontend/src/components/sheet/askAiPrompts.ts`

A typed catalog of prompts. Each entry:

```ts
export type AskAiPrompt = {
  id: string;
  title: string;        // short label shown in the dropdown
  description: string;  // one-line "what this does"
  group: "analyze" | "transform" | "selection";
  build: (ctx: AskAiContext) => string;  // returns the message text
};

export type AskAiContext = {
  projectName: string;
  sheetName: string;
  degreeType?: string;
  columns: { name: string; type: string }[];   // excludes 'group' cols
  rowCount: number;
  selectionCount: number;                       // 0 if none
  selectedRowSummary?: string;                  // e.g. "3 rows selected" or focused cell
  focusedCell?: { rowIndex: number; colName: string } | null;
};
```

**~9 prompts** (each `build()` produces a natural-language message phrased to trigger the existing action planner):

*Analyze*
- **Summarize this sheet** — "Give me a status breakdown of sheet X…" (→ `analyze_sheet`)
- **Find approaching deadlines** — "List rows with dates in the next 30 days…" (→ `get_deadlines` / `filter_rows`)
- **What's missing?** — "Which columns have empty values across most rows, and which rows look incomplete?" (→ `get_column_values` / `filter_rows is_empty`)
- **Suggest next steps** — "Based on this sheet's structure, what 3 actions should I take this week?" (read + advisory)

*Fill & Transform*
- **Draft outreach emails** — "Add an email draft column and draft a first-contact email for each professor/university row" (→ `add_column` + `bulk_update_rows`)
- **Categorize by status** — "Group these rows into Ready / In Progress / Blocked based on the Status column" (→ `bulk_update_rows`)
- **Add a priority score column** — "Add a 'Priority' number column and score each row by deadline proximity and status" (→ `add_column` + `bulk_update_rows`)
- **Enrich rows** — "For each university row, add a Country/Region column if missing and fill it" (→ `add_column` + `bulk_update_rows`, AI uses its own knowledge)

*Selection-aware* (only shown when `selectionCount > 0` or `focusedCell`)
- **Act on selected rows** — "I've selected N rows. Suggest bulk updates I could apply (status, tags, dates)." (→ `bulk_update_rows`)
- **Fill this cell** — (focused-cell only) "Suggest a value for the '<col>' cell in row N based on the row's other data." (→ `update_row`)

The `build()` functions embed the project/sheet name and column list so the planner's name-resolution finds the right target without ambiguity.

## Why this satisfies "AI must have data & action control"

The prompts are phrased as **imperative action requests** ("add a column and fill it", "categorize these rows", "draft emails for each row"). FloatingAssistant's existing `looksLikeWorkspaceAction` detector routes them to `/ai/actions/plan`, which emits a structured JSON plan, and `/ai/actions/execute` runs the real `add_rows` / `bulk_update_rows` / `add_column` against `project_pages.rows_json`. Writes show Confirm/Cancel (already built). The AI is genuinely mutating the sheet — not returning text the user has to copy-paste.
