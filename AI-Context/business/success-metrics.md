# Success Metrics

ScholarDocX succeeds if it replaces scattered tools with one private local application workflow.

## Product Success Metrics

- User can track all active applications from one dashboard.
- User can find next deadlines without checking spreadsheets or calendars manually.
- User can link documents to specific applications.
- User can draft and version SOPs, proposals, and email templates in one place.
- User can track professor outreach and follow-up reminders.
- User can use AI research without moving the core data store to the cloud.

## Operational Success Metrics

- App runs locally with no hosted backend.
- First launch creates required local workspace folders.
- Project can be extended by AI agents with minimal repeated context loading.
- No source file exceeds the file-size policy without task-level justification.
- Core workflows have unit tests before they become heavily depended on.
- Each feature includes unit tests when meaningful behavior is introduced, or records why unit tests were not needed.

## MVP Success Definition

MVP is successful when a user can:

- Create degree workspaces.
- Add countries, universities, programs, and professors.
- Track application status and deadlines.
- Store and link files.
- Draft at least one rich-text document per application.
- Create an email template and log a sent outreach.
- Configure AI keys and run one research-assisted query.
