# Plan: Rebuild Plan Pricing as a table; move AI credits here from Role Limits

## Goal
Replace the current Plan Pricing modal (3 static cards, single bulk-save) with an inline-edit **table** matching the AI Credit Packs (TokenPacksTab) UX — one row per plan, with per-row Save/Revert, dirty-state tracking, and a Refresh button. **Move `ai_tokens_per_month` (monthly AI credits) out of `role_limits` into `app_settings`**, so credits are managed here alongside prices, not in Role Limits.

Shows all 4 tiers: **Free, General, Pro, Max**.

---

## Backend changes

### 1. `app/db/schema.py` — seed the new credit keys
Add to the `app_settings` INSERT block:
- `plan_ai_credits_free` = `0`
- `plan_ai_credits_general` = `500000`
- `plan_ai_credits_pro` = `2000000`
- `plan_ai_credits_max` = `5000000`

(Mirrors the current `ai_tokens_per_month` values in `DEFAULT_ROLE_LIMITS`.)

### 2. `app/services/ai_tokens.py` — `get_role_monthly_allowance()` (lines 109-118)
Change the read source from `role_limits` to `app_settings`:
```
SELECT value FROM app_settings WHERE key = 'plan_ai_credits_<role>'
```
Map role → key (`free_user`→`plan_ai_credits_free`, etc.). Fallback to 0 if missing. This is the **only** runtime read path, so this is the core wiring change.

### 3. `app/services/admin.py`
- **`update_app_setting()`** (line 932): when `key` starts with `plan_ai_credits_`, run the same `FORCE_RESET` propagation on `ai_token_balances` that `update_role_limit` currently does for `ai_tokens_per_month` (lines 688-700) — so a credit change takes effect immediately for existing users instead of at next month boundary.
- **`DEFAULT_ROLE_LIMITS`**: remove the `ai_tokens_per_month` entries from all 4 user tiers (free/general/pro/max). They're now managed via app_settings, not role limits. (Keep `can_use_*`, `total_*`, etc.)

### 4. `app/api/auth.py` — `GET /auth/plans` (lines 301-329)
Keep the response backward-compatible:
- `pricing` object: **add** the 4 `plan_ai_credits_*` keys (frontend will read them).
- `plans` object: keep returning `ai_tokens_per_month` per role so `PlanComparisonView` keeps working — inject it back from `app_settings` so the shape is unchanged even though it's no longer in role_limits.

### 5. Re-seed the live DB
Run `initialize_database()` to add the 4 new `plan_ai_credits_*` settings. Then manually remove the `ai_tokens_per_month` rows from `role_limits` for the 4 user tiers (they're now dead/orphaned) and backfill the app_settings defaults.

## Frontend changes

### 6. `src/components/admin/RoleLimitsTab.tsx`
The `ai_tokens_per_month` row will naturally disappear from user tiers (it's no longer seeded in role_limits). The feature-group definition for `ai_tokens_per_month` (in `featureGroups`) can stay harmlessly — empty groups are already skipped (the fix from earlier). No change strictly required; optionally remove it from the `coreFeatures` array to avoid confusion.

### 7. `src/components/admin/SettingsTab.tsx` — replace the Plan Pricing modal
Replace the current `showPricingModal` block (the 3 static cards + bulk-save) with an inline **table** modeled on `TokenPacksTab.tsx`:

| Plan | Monthly Price (৳) | Yearly Price (৳) | Monthly AI Credits | Actions |
|------|------|------|------|------|
| Free | (disabled, $0) | (disabled, $0) | [input] | Save/Revert |
| General | [input] | [input] | [input] | Save/Revert |
| Pro | [input] | [input] | [input] | Save/Revert |
| Max | [input] | [input] | [input] | Save/Revert |

- Each row is a draft with dirty-state tracking (`isSame`), per-row Save + Revert buttons, exactly like TokenPacksTab.
- Free row: price inputs disabled/locked at 0 (Free is free); only Credits is editable.
- Credits input formatted with the `formatTokens` helper (K/M).
- Save calls `PATCH /admin/settings/{key}` for each changed key (6 price keys + up to 4 credit keys). Reuses existing `handleUpdate` + the FORCE_RESET propagation now lives server-side (step 3).
- Keeps the same modal trigger button ("Configure") and card on the settings grid — only the modal body changes to a table.
- Preserve the Refresh button + skeleton loading + empty state patterns from TokenPacksTab.

### 8. `src/components/PlanComparisonView.tsx` (no code change expected)
It reads `ai_tokens_per_month` from `plans.<role>`, which the backend still injects (step 4). Verify only.
