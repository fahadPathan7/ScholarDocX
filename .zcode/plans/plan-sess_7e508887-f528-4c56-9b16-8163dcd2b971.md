## SCHOLARDOCX-0156: Lock (non-editable) email on Polar checkout page

### Goal
When a user opens Polar's hosted checkout, their ScholarDocX account email must be **pre-filled and non-editable**, so the buyer can't typo a different address (which today breaks webhook reconciliation).

### Root cause
`backend/app/api/auth.py:431-435` — `create_polar_checkout` builds the Polar request with only `product_id` + `success_url`. The `customer_email` field is accepted by `PolarCheckoutPayload` but dropped from `req_body`, so Polar shows an empty editable email field.

### Approach (backend-only)
Use `current_user` as the authoritative customer source (NOT the client-supplied `payload.customer_email`) and pass Polar the identifier that makes it treat the customer as "known" (→ email locked):

- **Returning customer** (`current_user["polar_customer_id"]` is set) → pass `customer_id: polar_customer_id`. Polar finds the existing customer, locks email.
- **New customer** (no `polar_customer_id`) → pass `external_customer_id: current_user["id"]` (our user UUID) + `customer_email: current_user["email"]`. Polar creates a new customer with our external ID set, locks email.

This avoids duplicate Polar customers: known users reuse their Polar customer; brand-new users get one created with our external ID. Webhook reconciliation still works via the email fallback for new customers.
