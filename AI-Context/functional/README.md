# Functional Context

This folder describes what ScholarDocX must do from the user's perspective.

## Files

- [requirements-index.md](requirements-index.md): numbered functional requirements.
- [feature-map.md](feature-map.md): feature areas and dependency relationships.
- [feature-initialization-workspace.md](feature-initialization-workspace.md): first-run setup and environment validation.
- [feature-dashboard-hierarchy.md](feature-dashboard-hierarchy.md): degree, geography, institution, program, professor, dashboard.
- [feature-project-workspace.md](feature-project-workspace.md): project workspaces, sheet-like pages, notifications, and layout behavior.
- [feature-documents-storage.md](feature-documents-storage.md): document playground, versioning, static files.
- [feature-email-outreach.md](feature-email-outreach.md): templates, attachments, mailto, reminders.
- [feature-ai-assistant.md](feature-ai-assistant.md): chat, Tavily research, GLM drafting support.
- [feature-authentication.md](feature-authentication.md): optional local identity and Google OAuth guidance.
- [feature-about-profile.md](feature-about-profile.md): profile/about placement and main UI copy rules.
- [domain-relationships.md](domain-relationships.md): entity relationships and workflow links.
- [acceptance-criteria.md](acceptance-criteria.md): high-level acceptance criteria by module.

## When To Update

Update this folder when behavior changes:

- User workflows
- Feature scope
- Requirement IDs
- Entity relationships
- Acceptance criteria
- UX expectations
